V1.0.0

Change Description (launch.sh - critical portability fix, "No boot" issue)
Fixed three loops that used bash-only process substitution ("done < <(find ...)") in check_roms_sizes / analyze_disk_usage and check_roms_names. Because the pak's shebang is "#!/bin/sh", NextUI executes it with dash / busybox ash, neither of which understand this bash syntax. The result was a hard parse error on the ENTIRE script, so the pak failed to launch at all, with no log ever written. This is the root cause reported in Issue #2 ("No boot", NextUI v6.60, ROM Inspector v0.9.0).
Replaced each occurrence with a POSIX-compliant pattern: "find ... > tmpfile" followed by "while IFS= read -r VAR; do ... done < tmpfile", which preserves variable values set inside the loop (unlike piping into the loop, which would run it in a subshell) without relying on any bash-only feature.
Verified the fix by running the full script through both "sh -n" and "dash -n" with zero syntax errors (previously failed immediately at the first occurrence).
Affected: check_roms_sizes / analyze_disk_usage loops, check_roms_names function, log ($LOGS_PATH/Rom Inspector.txt).
Purpose: Restore pak startup on NextUI/TrimUI Brick.
Commit Message: "Fix critical POSIX portability bug: replace bash-only process substitution with temp-file redirection, resolving pak boot failure (closes #2)."

Change Description (launch.sh - startup ordering)
Reordered the startup sequence so that LOGS_PATH is created (mkdir -p) before the very first log line is written. Previously the first "Initializing: ..." log entry was written before the logs directory existed, so on a completely fresh install that first line was silently lost.
Affected: startup section at the top of launch.sh.
Purpose: Make logging reliable from the very first run, which also makes future bug reports easier to diagnose.
Commit Message: "Create LOGS_PATH before first log write to avoid silent logging failure on fresh install."

New feature (Trash / safety net for deletions)
Added a trash system: ROMs, covers, orphaned files, ZIP archives, and files removed via the ROM name cleanup tool are no longer permanently deleted immediately. They are moved to "Tools/tg5040/Rom Inspector Trash" by a new trash_file() helper, which falls back to a real "rm -f" only if the move itself fails (e.g. no space left), so behaviour is never worse than before.
Added a new "Manage Trash" entry in the main menu showing the number of files and total size currently in the trash, with an "Empty trash" action that still requires the existing confirm_deletion confirmation dialog before permanently freeing the space.
Updated user-facing confirmation messages from "Deleted: X" to "Moved to trash: X" so it is clear the action is reversible.
Implemented using only utilities already used elsewhere in the script (mv, mkdir, date, find) - no new dependency was introduced.
Affected: confirm_deletion-driven deletions across check_roms_sizes, remove_duplicate_roms, list_orphaned_files, check_roms_names, Manage_zip_roms; new functions trash_file(), trash_size_bytes(), empty_trash(), manage_trash(); main menu (/tmp/main_menu.menu).
Purpose: Give users a real safety net against accidental deletions, addressing the single biggest risk of a tool whose main job is deleting files.
Commit Message: "Add trash-based deletion (trash_file) and Manage Trash menu, replacing permanent rm -f across all delete paths."

V1.1.0

New feature (Restore from trash)
Added the ability to restore a file straight back to its original location instead of only being able to empty the trash. trash_file() now writes a small ".origin" sidecar text file next to every trashed item, recording its original absolute path.
Added restore_file() to move a trashed file back, recreating its original folder if needed, and automatically renaming it to "<name> (restored)" instead of overwriting anything if a file already exists at that path.
Added restore_from_trash(), an interactive menu listing every file currently in the trash; picking one restores it immediately (no confirmation needed, since restoring is a non-destructive action).
Added a "Restore a file" entry to the "Manage Trash" menu, alongside "Empty trash". Trash file/size counts now correctly exclude the ".origin" sidecars.
Implemented using only utilities already used elsewhere in the script (mv, mkdir, cat, printf, find) - no new dependency was introduced.
Affected: trash_file(), new functions restore_file() and restore_from_trash(), manage_trash() menu, cleanup() temp file list.
Purpose: Make the trash safety net actually useful for recovering from a mistake, not just a delayed-delete buffer.
Commit Message: "Add restore-from-trash (restore_file/restore_from_trash) using .origin sidecars, plus Restore menu entry."

New feature (Free space check before ZIP decompression)
Added check_disk_space_for_zip(), which reads the archive's uncompressed size from "unzip -l" (already a dependency of Manage_zip_roms) and compares it against the free space reported by "df -Pk" on the destination directory, with a 5% safety margin (minimum 5 MB). If there isn't enough room, extraction is skipped instead of attempted, the attempt is logged as "Skipped (not enough free space)" in zip_roms_report.txt, and (in the interactive single-ROM flow) the user sees an explicit error message instead of a silent partial extraction.
Fails open by design: if the uncompressed size or the free space can't be determined, the check is skipped and extraction proceeds as before, so it can never block a valid extraction that used to work.
Affected: Manage_zip_roms (all three decompression call sites), new function check_disk_space_for_zip(), report (zip_roms_report.txt), log ($LOGS_PATH/Rom Inspector.txt).
Purpose: Prevent a ZIP decompression from failing halfway through and leaving a corrupted/partial ROM on an SD card that was nearly full.
Commit Message: "Add check_disk_space_for_zip() and check free space before every ZIP extraction in Manage_zip_roms."

New feature (Export Collection Inventory)
Added a new "Export Collection Inventory" entry to the main menu. It walks every system under /mnt/SDCARD/Roms using the same valid-extension matching as the rest of the script (get_valid_extensions / is_valid_extension), and writes a single manifest, collection_inventory.txt, listing every valid ROM name grouped by system, with a total game/system count at the top.
Useful as a plain-text backup of "what I own" before reformatting an SD card, or to compare two cards.
Implemented using only utilities already used elsewhere in the script (find, cat) - no new dependency was introduced.
Affected: new function export_collection_inventory(), new report (collection_inventory.txt), main menu (/tmp/main_menu.menu), cleanup() temp file list.
Purpose: Give users an easy way to keep a record of their collection independent of the ROM files themselves.
Commit Message: "Add export_collection_inventory() and 'Export Collection Inventory' main menu entry."
